Agentic AI is an artificial intelligence system that can act autonomously or semi-autonomously to achieve a specific goal, with limited or no human supervision. It operates independently, without continuous human hand-holding or step-by-step prompts.

IBM’s definition

A chatbot stops at the reply

You ask, it writes. You still do the clicking, searching, and checking.

step 5
is the split

An agent gets another go

The stock number it just pulled can change what it does next. One result leads to the next step.

If someone asks “is a chatbot an agent?”: only if it chooses tools and keeps going from their results. A single reply is not an agent. Searching documents is a tool an agent might use. It is not the agent by itself.

02 · See the difference

Same question, two very different helpers

Say a student tells you: “I can't log in to the portal.”

same question, two helpers

Chatbot

Gives you a polite checklist: reset your password, try another browser, clear the cache. You still have to dig through the logs and account page yourself.

Agent

Reads the login log, checks the account service, then tells you “locked after 5 wrong passwords at 8:14pm.” You decide whether to unlock it.

02 · When to use it

So what's an agent actually good for?

Only bring in an agent when your work looks like one of these

One question, lots of screens

“Where's my parcel?” needs the order, the payment, and the courier. A person opens three tabs. An agent can go through all of them in one go.

The work is a checklist

Reset a password. Quote a PC. Run the tests. Steps in a row? Perfect for an agent. “What time do you open?” is just an FAQ, no agent needed.

People are the bottleneck

Think helpdesks and code review. The agent prepares the answer or the patch, and you make the final call.

03 · Knowledge graph

A knowledge graph stores the links, not the paragraphs

Each fact is a node. The rule between two facts is an edge. You ask “what is this connected to?” and walk the line.

DDR4 stick

a part in the catalog

→

does not fit

the edge, the rule

→

DDR5 board

the other part

A paragraph search would only find text that mentions DDR4. The graph answers the link: this stick does not fit this board. That is the question a shelf cannot answer.

03 · Knowledge graph · jobs, tools, examples

Use it when the answer is a path

Will this fit?

A RAM kit, a board, a power supply. Eligibility is the same shape: this plan, this add-on, this ID check.

What do I check next?

A fault, then the next test, then the fix. The steps are linked. The agent walks them instead of inventing a procedure.

Who is tied to whom?

Accounts, devices, and payments that share an edge. Useful for fraud, and for “this customer already has that plan.”

Neo4j

nodes, edges, Cypher queries

Amazon Neptune

the same idea, on AWS

GR

GraphRAG

Microsoft’s graph over documents

Fastweb + Vodafone keep their call-centre troubleshooting steps in Neo4j. The agent walks that path and briefs the person on the phone. It does not talk to the customer. In the PC shop, “will this DDR4 kit run on that DDR5 board?” is the same kind of question. Today the shop answers it with rules in code, not with Neo4j.

Cypher is Neo4j’s query language. One sentence is enough: you ask for a pattern, like a part connected by “does not fit” to a board. GraphRAG builds a graph out of documents so questions can follow entities, not only similar paragraphs. Do not claim the Apex inventory service is a graph database. The compatibility rules live in the inventory code.

06 · What got cheap

Drafts got cheap. Good judgment didn't.

One draft, two different costs.

what got cheap, and what didn't

Coding

A first version of an API, a mapper, or a test that follows a rule you already wrote. Some companies already let AI review pull requests, but a human still has to check. In our shop, the agent can fix the branch, but a human still merges.

A whole system

Setting up services, a gateway, and a database is cheaper than before. Designing the boundaries, keeping it running, and scaling it? Not so much. Someone still has to know that a failed charge must put the stock back.

If a student says “so I should not learn Java”: the demo is Java, and the agent is pointed at Java rules. The language is not the moat. The moat is knowing why the rule exists. AI code review exists. It does not replace the person who can see a wrong boundary.

06 · Who spots the problems

Looks great if you don’t know the topic. Not so great if you do.

Same new API. It compiles. It returns 200.

depends on who's looking

A junior, one prompt

You ask for a new API. It compiles. The endpoint returns 200. From the outside, it looks done.

A senior, the same API

The SQL reads the whole table. The same check is written twice. The endpoint trusts whatever the client sends. The junior couldn't see any of that, so nobody asked the AI to fix it.

AI looks really good in a field you don't know, because you can't see what it skipped. To someone who does know, it looks weak.

06 · The tool and the person

Same AI. The prompt is the skill.

Same payment gateway (we're keeping XX unnamed). Same AI model.

the prompt makes the difference

Prompt A · junior

Create a new DuitNow online payment API from payment gateway XX.

Prompt B · senior

Create a new DuitNow online payment API using payment gateway XX. Make it atomic: if the charge sticks halfway, roll it back so nothing is left hanging. Make it idempotent: if the app freezes, or the network is slow, and the user taps pay again, do not charge them twice.

Atomic means the payment either goes all the way through or gets rolled back. Idempotent means if you repeat the same payment, you don't get charged again. AI is still just a tool. The person who knows the field is the one who can point it at a better product.

Read both prompts out loud. Do not rush Prompt B. The senior is not asking for more code. They are naming the failure: a stuck transaction, and a double tap when the app hangs. That is the domain. XX stays unnamed on purpose. Do not invent a gateway.

The years it takes to turn a junior into that person. Teams want an expert from day one, but fewer want to train one.
